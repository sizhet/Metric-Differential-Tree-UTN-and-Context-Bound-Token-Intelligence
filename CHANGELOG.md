## Added — Metric-Differential Tree

Established the **Metric-Differential Tree (MDT)** as the structural substrate for UTN.

MDT organizes Context Starmaps according to:

```text
Metric Similarity
Metric Distance
Differential Boundaries
Structural Neighborhoods
```

The MDT converts a potentially global typing problem into localized structural decisions.

Canonical principle:

> **Localize first; compare locally.**

## Added — Typing-First, Naming-Second UTN

Separated Universal Typing and Universal Naming into two distinct stages.

### Universal Typing

Determines:

```text
Can these structural individuals share a type?
```

using:

```text
metric evidence
context compatibility
counter-evidence
policy
historical cases
validation
```

### Universal Naming

Determines:

```text
What symbolic name should represent the validated type?
```

using:

```text
existing vocabulary
domain terminology
aliases
LLM suggestions
historical naming
human policy
```

Established the canonical rule:

> **UTN is Typing-first, Naming-second.**

## Added — Structural Identity Model

Separated structural identity from human-readable naming.

Established four conceptual layers:

```text

        ↓

        ↓
```

Established:



## Added — Leaf Preservation

Established the **Leaf Immutability Principle**.

MDT leaves preserve individual structural evidence including:

```text
original context
original name
source
version
provenance

```

Canonical rule:

> **Fold upward; do not erase downward.**

Parent types may evolve without destroying original leaf evidence.

## Added — Parent Structural Types

Defined MDT parent nodes as candidate or validated structural types representing commonality among descendants.

Established:

> **Typing does not have to wait for Naming.**

A parent structural identity may exist before receiving a final human-readable canonical name.

## Added — Two-Way Structural Search

Instead of:



Established:

> **Similarity creates candidates, not truth.**

## Added — Domain / Space / Time Context Model

Established **Domain / Space / Time (D/S/T)** as the first canonical context factorization.

### Domain

```text

```

### Space

### Time

This provides a compact first experimental context coordinate system.

## Added — Baseline-Preserved Context Injection

Introduced **Baseline-Preserved Context Injection (BPCI)**.

Canonical relation:

```text
S1 = S0 + C
```

where:

```text
S0 = baseline input
C  = explicit context augmentation
S1 = context-enhanced input
```

with the required invariant:

```text
Recover(S1) = S0
```

Established:

> **Every context-enhanced input should preserve a mechanically recoverable context-free baseline.**

This gives each context-enhanced inference a natural control group.

## Added — Context Gain

Defined **Context Gain** as the task-specific difference between context-enhanced and baseline performance.

Conceptually:



The repository explicitly avoids assuming that additional context is always beneficial.
